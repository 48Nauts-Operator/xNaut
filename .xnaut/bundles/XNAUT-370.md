# XNAUT-370 — Machine roles: `dispatch_here` becomes `instance.role`, and every record is signed

Branch `agent/claude/xnaut-370`, worktree
`/Users/zelda/DevHub_Studio/factory/02-Development/xnaut-worktrees/agent-claude-xnaut-370`,
off `dev` at `5463538`.

## What changed

On 2026-09-13 the Studio and tron ran different builds of the same app against
the same board. Two bugs came out of that, and the drift was invisible because
no record said which machine wrote it. This ticket does two things about that.

**A machine states what it is for.** `instance.role` in settings, three values:

| role | dispatches | verifies |
|---|---|---|
| `fleet` | yes | yes |
| `workstation` | **no** | no |
| `sandbox` | no | yes |

The capability table is stated once, as methods on `instance::Role`, so three
switches cannot be configured into a contradiction. `loops.dispatch_here` is
read as an alias and left on disk for one release, so a settings file written by
this build still reads correctly in the build before it — which is the exact
two-machines-two-versions case this ticket is about.

An **empty** role reads as `fleet`: `dispatch_here` defaulted to true and every
machine has had that default until now, so a fresh install behaves exactly as it
did yesterday. A role this build **cannot parse** reads as `workstation` — a
machine whose purpose is unclear must not start agents on somebody's desk. The
ticket waits and the ledger says why, which is a visible failure rather than a
dangerous one.

**Every record is signed.** `ledger::Entry` and `run_control::RunManifest` gained
`instance`, `role` and `version` (`app_version` on the manifest), all
`serde(default)` so the ~60 ledger lines and 241 manifests that predate them
still parse. Empty means UNKNOWN, never "this machine" — the same rule the
`session` field already keeps, and for the same reason.

The Observatory grew a **This instance** card (role first, because that is what
decides whether the machine may start work) and a **Ledger** band where each line
carries its signature chip: yellow for this machine, red for a line written by a
different build, dashed "unsigned" for one written before signatures existed. The
band header counts distinct instances, so `2 instances` is readable rather than
something you have to notice.

The sweep's dispatch gate moved from the boolean to `role.dispatches()`, and the
verify arm gained the matching `role.verifies()` gate — a verification is a run
too, and the whole reason the workstation role exists is that runs must not start
on the owner's desk.

### Deliberately not done

- **A workstation no longer verifies either.** The old `dispatch_here: false`
  stopped dispatch only. The role names say `workstation` plans and reviews, so
  the migration from `dispatch_here: false` also stops verification on that
  machine. tron is unaffected (`fleet`); the Studio will stop offering
  verifications, which is the intended reading of the role.
- **No UI to change the role.** It is one line in `settings.json`. The realm
  (XNAUT-371) is where an instance registers and gets its role from a key, and
  building a settings toggle now would be a surface to delete then.
- **No realm, no join, no heartbeat.** XNAUT-370 is the local half: the id is
  minted here and saved here. XNAUT-371 is where it is registered.
- **`preflight.rs` was left alone.** It reports why NautBot will not work on this
  machine and never read `dispatch_here`; making it role-aware is a separate,
  visible change.

## The key code

The capability table, stated once (`instance.rs`):

```rust
impl Role {
    /// May this machine start agents? Only the fleet.
    pub fn dispatches(self) -> bool {
        matches!(self, Self::Fleet)
    }

    /// May this machine start verifications? The fleet and a sandbox box.
    pub fn verifies(self) -> bool {
        matches!(self, Self::Fleet | Self::Sandbox)
    }
}
```

Three cases, and the middle one is the interesting one (`instance.rs::resolve`):

```rust
let configured = settings.instance.role.trim();
if configured.is_empty() {
    return Role::Fleet;          // what dispatch_here: true meant
}
Role::parse(configured).unwrap_or(Role::Workstation)   // unreadable: start nothing
```

The refusal line has to name the machine AND repeat byte-for-byte, or the "says
so once" dedup cannot suppress it (`sweep.rs`):

```rust
pub(crate) fn refusal(what: &str, role: crate::instance::Role) -> String {
    format!(
        "this instance is a {} on xNAUT {}; it does not {what} — the ticket waits for an \
         instance that does",
        role.as_str(),
        env!("CARGO_PKG_VERSION"),
    )
}
```

A registry event is signed by the RUN, not by whoever is reading the registry
(`ledger.rs::record_run_in`):

```rust
instance: run.instance.clone(),
role: run.role.clone(),
version: run.app_version.clone(),
```

The migration writes nothing on read; `main.rs` setup is the one caller allowed
to persist (`instance.rs::adopt`, `settings.rs::load_or_default`):

```rust
// The role the legacy `loops.dispatch_here` implies, for THIS reader only.
crate::instance::adopt_role(&mut settings);
```

## How to verify by hand

```bash
cd /Users/zelda/DevHub_Studio/factory/02-Development/xnaut-worktrees/agent-claude-xnaut-370

# Both suites.
cargo test --manifest-path src-tauri/Cargo.toml
XNAUT_TEST_PORT=4291 npx playwright test

# A workstation refuses, once, in words that name it.
cargo test --manifest-path src-tauri/Cargo.toml \
  a_workstation_refuses_in_the_same_words_every_tick_and_names_which_machine -- --nocapture

# A ledger line carries the signature, and an old line still parses.
cargo test --manifest-path src-tauri/Cargo.toml ledger:: -- --nocapture

# The deck, against a stubbed two-instance ledger.
XNAUT_TEST_PORT=4291 npx playwright test observatory-instance
```

In the running app: open the Observatory. The first card reads **This instance**
with the role as its headline, the hostname beside it, and the short key plus the
build below. Every line in the Ledger band at the bottom carries the same chip —
yellow where this machine wrote it, red where a different build did.

To watch a machine refuse: set `"instance": {"role": "workstation"}` in
`~/Library/Application Support/xnaut/settings.json`, restart, and leave a ready
owned ticket on the board. One `sweep_refused` line appears in the Ledger band
naming the role and the version, and no second one arrives on the next tick.

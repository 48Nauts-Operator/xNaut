## What changed

**The finding first:** no Council integration. NautFlow already *is* a council
run in sequence, so wiring Council's five members in front of it debates the
same question twice out of the same knowledge. The one member worth taking is
the Researcher, because no NautFlow stage had live external knowledge.

1. **A Researcher in the seed.** `default_researcher_profile` — `@researcher`,
   role `researcher`, provider `perplexity`, model `sonar-pro`, capabilities
   `research` + `search`, read-only with no shell — added to `default_profiles`,
   so a fresh install seeds it and an existing install gets it through
   `reconcile_profiles` (the XNAUT-301 path), with a deletion still sticking.
2. **`research.rs`, the seam.** `research_status` resolves who will research
   from the profile store and settings alone (no network, no tokens);
   `research_brief` asks the question and returns the answer with its sources.
   "No profile" / "no key" / "provider we cannot call for research" are three
   different `available: false` reasons, never an `Err` — a missing optional key
   must not look like a broken app.
3. **`ai.rs` learned to cite.** `Citation { title, url }`, `citations` on
   `AiResponse`, `extract_citations` reading both Perplexity shapes
   (`search_results` with titles preferred, bare-URL `citations` filling in),
   deduplicated by URL, sources without a URL dropped. Plus an optional `system`
   prompt, because "you are an expert terminal assistant" is the wrong
   instruction for a market-context question.
4. **NautFlow asks before it writes.** The Analyst and Architect stages (and no
   others) fetch a brief in `runPersonaHeadless` and append it to the persona
   goal with numbered sources and a rule: cite from this list only, and treat it
   as evidence that never overrides the owner contract. Chat follow-ups
   (`opts.raw`) do not re-search.
5. **It says what it did.** The stage card carries
   `researcher · @researcher · perplexity · sonar-pro`, or
   `Researcher unavailable — <reason>`; the run panel logs the same on both
   paths, so an unresearched run cannot be mistaken for a researched one.
